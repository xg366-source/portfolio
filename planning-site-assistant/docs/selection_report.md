# 检索与生成选型报告（2026-10-27，v3）

## 结论先行

| 决策 | 结论 |
|---|---|
| 文档检索主路线 | **保留 BM25**。在现有评估集与探针集上，TF-IDF 与 BM25 表现完全相同，迁移没有收益，只有成本。 |
| TF-IDF 地位 | **验证过的等价平替**：端到端 40 题全过（余弦拒答阈值 0.22），可随时替换，但没有替换的理由。 |
| 稠密 embedding | **暂不引入**。它需要外部 embedding API key（目前没有），且本报告证明：在现有语料规模下，稀疏方法之间的差异测不出来——只有当探针集能证明 embedding 在同义改写上胜出时，才值得引入。 |
| 数字类问题 | **继续走 GIS 结构化查询，不进检索**。这是架构决策，不受本次对照影响。 |
| 生成模式 | **待 Key**。cite-or-refuse 提示词已留（`build_llm_prompt`），生成回答的引用准确率与幻觉率对照需 DeepSeek key 到位后才能跑，本报告不编造这部分数据。 |

## 实验设计

### 评估集构成（40 题，v2，2026-10-24 扩集，2026-10-27 复测全过）

| 类别 | 题数 | 说明 |
|---|---|---|
| 文档事实 doc_fact | 14 | 答案在规划文件原文中 |
| GIS gis_rank / profile / median / correlation | 9 | 走结构化查询，不参与检索对照 |
| 跨源 cross_source | 5 | 需拼两处以上的事实 |
| 拒答 refusal | 8 | 资料库外的问题，必须拒答 |
| 口径陷阱 trap | 4 | 分母、报案≠定罪、样本量门槛 |

### 对照范围（诚实边界）

- 检索对照只覆盖**文档路线 23 题**（doc_fact 14 + cross_source 5 + trap 4）。GIS 9 题按设计走结构化查询，不计入检索指标；拒答 8 题只用于拒答信号分析。
- 指标：Recall@5（期望来源是否在前 5 引用中）、Recall@1、MRR@5。排序质量用**无阈值**方式比，因为 BM25 分数与余弦分数不在同一量纲，共用一个阈值会操纵结果。
- TF-IDF 说明：本报告的“向量”是 **TF-IDF 余弦（稀疏向量）**，与 BM25 共用同一分词（单字 + 双字）和同一语料，隔离出的只是排序函数本身的差异。**它不是稠密 embedding**，不能匹配无字面重叠的同义词——这个局限正是探针集要测的东西。
- 探针集（`eval/probe_questions.jsonl`，10 题）：把问题换成与原文不同的说法（如“这片地方一共住了多少人？”、“小地方算人均指标为什么不准？”），**不计入 40 题 headline 指标**，只用于检验区分度。

### 复现命令

```bash
python3 eval/run_eval.py            # 端到端 40 题（BM25）
python3 eval/compare_retrieval.py   # BM25 vs TF-IDF 排序对照
python3 eval/run_probe.py           # 10 题探针 + TF-IDF 端到端检查
python3 tests/test_core.py          # 核心行为测试（5 项）
```

## 结果

### 排序对照（文档路线 23 题）

| 指标 | BM25 | TF-IDF | 分歧题 |
|---|---|---|---|
| Recall@5 | 1.00 | 1.00 | 0 |
| Recall@1 | 1.00 | 1.00 | 0 |
| MRR@5 | 1.00 | 1.00 | 0 |

分品类（doc_fact / cross_source / trap）三项指标两边均为 1.00。

### 探针集（10 题改写问法）

| 指标 | BM25 | TF-IDF |
|---|---|---|
| Recall@5 | 1.00 | 1.00 |
| Recall@1 | 0.80 | 0.80 |
| MRR@5 | 0.883 | 0.883 |

两题未进首位（p-01 排第 3、p-03 排第 2），两边排名**完全一致**。改写问法没有拉开差距。

### 端到端（40 题全量）

| 路线 | 结果 |
|---|---|
| BM25（现行阈值：分数 ≥2.0 且词覆盖 ≥0.30） | 40/40 通过：Recall@5 1.00、答案含关键值 1.00、拒答准确率 1.00、过度拒答 0 |
| TF-IDF（余弦阈值 0.22 + 词覆盖 ≥0.30） | 40/40 通过 |

核心行为测试 5 项全部通过。

## 拒答信号分析（本报告最值得注意的一节）

| 信号 | 可答题 top-1 | 不可答题 top-1 | 能否分开 |
|---|---|---|---|
| BM25 分数 | 最低 12.32 | 最高 6.82 | 能分开，但**现行阈值 2.0 低于不可答最高分**——分数本身拦不住拒答题 |
| 词覆盖 | — | — | 现行拒答实际靠**词覆盖 ≥0.30**兜底，分数是第二道信号 |
| TF-IDF 余弦 | 最低 0.286 | 最高 0.169 | 能分开，中点 0.22 可作阈值 |

两点诚实声明：

1. BM25 的拒答是**双信号**在起作用，不是单分数。只看分数会误判这套机制的安全性。
2. TF-IDF 阈值 0.22 是**在评估集上拟合出来的**（取可答最低与不可答最高的中点），上生产前必须用留出题验证，否则就是用考试题定分数线。

## 调优轮次记录（本轮实际发生的两件事）

1. **接口不一致导致端到端崩溃**：TF-IDF 类最初没有 `term_coverage` 方法，端到端检查直接报错。修复是把词覆盖抽成两类共享的模块级函数——拒答信号不能依赖于换了哪个排序函数，否则一次替换会悄悄改变拒答行为。
2. **阈值校准**：TF-IDF 余弦阈值按分布中点定为 0.22，端到端复测 40/40 后才采纳。没有为凑指标改题目或改答案。

## 为什么打平（不是“两种方法等价”）

打平的真正原因是评估条件，不是方法本身：

- 语料只有 **2 份文档、7 个 chunk**，排序空间太小，拉不开差距；
- 分词含单字 + 双字，对改写问法的容错已经很高，探针的改写幅度还不足以暴露稀疏方法的词表天花板；
- 40 题多按原文措辞编写，属于“分布内”测试。

所以正确结论是：**在这套评估集上，两种稀疏方法不可区分**。这不是一句空话——它直接决定了下一步该测什么：只有同义改写幅度更大、或语料规模更大的测试，才能让稠密 embedding 的价值显形。

## 什么会改变决策

1. **稠密 embedding key 到位后**：用同一探针集 + 新增 10 题大幅改写题（同义词、口语化、无原文关键词）跑三方对照。若 embedding 在探针 Recall@1 上明显胜出且拒答可控，再谈 BM25 + embedding 混合检索；若仍打平，则不引入。
2. **生成模式对照（待 Key）**：接 DeepSeek 后，同一批题跑抽取式 vs 生成式，对比引用准确率、幻觉率、单题成本与延迟，再定生成模式的上线条件。
3. **语料扩大后**：文档超过 2 份、chunk 数上百时，重跑本报告全部实验——小语料下的结论不外推。

## 局限

- 评估集题目由项目方编写，非独立标注；阈值拟合存在过拟合风险。
- 语料规模小（7 chunk），结论只适用于当前项目规模。
- 生成模式与稠密 embedding 的对照尚未跑，本报告不声称已覆盖。
